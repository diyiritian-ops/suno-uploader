# v51 二分机制改造：从"丢弃"到"占位"

> 2026-11-19。照 sunouploader 的 115 片真实数据结构改造脚本。
> **顺带发现并修复了一个从上线起就存在的死代码 bug。**

---

## 一、最重大的发现：脚本的二分从来没生效过

### 现象

改造前每次跑 0 移调，日志都是：

```
✗ 放弃（已切 0 层，6.0s）
✗ 放弃（已切 0 层，6.0s）
切片统计：共 5 片，成功 2，失败占位 3（d0=5）
```

**「已切 0 层」= 一次都没拆过。**

### 根因

```js
const MIN_SEG = 6;
if (depth >= MAX_DEPTH || dur / 2 < MIN_SEG) {
  // 放弃
}
```

- 切片长度 `dur = 6.0s`
- `dur / 2 = 3.0s`
- `MIN_SEG = 6`
- **`3.0 < 6` → 条件成立 → 直接放弃**

**6 秒的切片永远无法二分，因为拆完只有 3 秒。**

### 站点的做法

从 115 片真实数据看：

```
6.0 秒 → 3.0 秒内容 + 3.0 秒静音（补齐到 6 秒上传）
3.0 秒 → 1.5 秒内容 + 4.5 秒静音
```

**内容可以很短，靠补静音满足 Suno 的 6 秒下限。**

### 修复

```js
// 判断标准应该是「内容是否还值得拆」，不是「拆完是否能到 6 秒」
const MIN_CONTENT = 0.8;
if (depth >= MAX_DEPTH || dur / 2 < MIN_CONTENT) {
  // 放弃
}
```

`sliceToWav` 本来就会补静音到 `MIN_SEG`（第 210-211 行），所以拆出来的 3 秒会自动补齐。

### 修复效果

| | 修复前 | 修复后 |
|---|---|---|
| 二分日志 | `✗ 已切 0 层` | ✅ `⇢ 二分 6.0s → 3.0s × 2（第 1 层）` |
| 成功片数 | 2/5（3 段丢失） | **8/8 全成功** |
| 切片统计 | `d0=5`（全在第一层） | `d0=2 d1=6`（真的拆了） |
| 成品时长 | 只剩 2 段内容 | **30.0s 完整** |

## 二、占位机制改造

### 改造前的行为

二分失败 → `return []` → 这段「凭空消失」：
- 用户不知道哪段没了
- 不知道涉及多少时长
- 无法还原二分树

### 改造后（照站点做法）

```js
if (depth >= MAX_DEPTH || dur / 2 < MIN_CONTENT) {
  return [{
    clipId: null, t0, t1, semis: pitchSemis, depth,
    status: 'split',            // ★ 占位标记
    reason: depth >= MAX_DEPTH ? 'max-depth' : 'too-short',
    origDur: dur,
  }];
}
```

**父段保留在 `pieces` 里，标记 `status='split'`，`clipId=null`，从不上传。**

### 拼装时过滤

```js
const all = pieces.slice();
const usable = all.filter(p => p.status !== 'split' && p.clipId);
const placeholders = all.filter(p => p.status === 'split' || !p.clipId);

if (placeholders.length) {
  L('拼装过滤：' + all.length + ' 片 → 可用 ' + usable.length +
    '（跳过 ' + placeholders.length + ' 个失败占位）');
  const tree = {};
  placeholders.forEach(p => { const d = p.depth || 0; tree[d] = (tree[d] || 0) + 1; });
  L('  失败分布：' + Object.keys(tree).sort().map(d => 'd' + d + ':' + tree[d]).join(' '));
}

const sorted = usable.sort((a, b) => a.t0 - b.t0);
```

### 为什么不需要「合并」

**子段带着原始的 `t0` / `t1` 坐标**，放回时间轴天然对齐。
过滤 + 排序，就自动正确了 —— 这正是站点 `startSecond` / `endSecond` 的作用。

## 三、配套改动

### ① 统计要区分成功与占位

```js
const okPieces = pieces.filter(p => p.status !== 'split' && p.clipId);
const badPieces = pieces.filter(p => p.status === 'split' || !p.clipId);

log('上传完成: ' + okPieces.length + ' 块（原始 ' + total + ' 段，' + round + ' 轮）');
if (badPieces.length) {
  const lostSec = badPieces.reduce((a, p) => a + (p.t1 - p.t0), 0);
  log('⚠ 有 ' + badPieces.length + ' 个占位未成功（涉及 ' +
      (lostSec * Math.pow(2, PITCH / 12)).toFixed(1) + 's 原始时长），拼装时会跳过');
} else {
  log('✓ 完整性校验通过：' + total + ' 段全部覆盖');
}
```

**以前会误报「全部覆盖」**（因为 `pieces.length` 计数含占位）。

### ② clipId 选择要跳过占位

```js
// 以前：if (!s.clipId && results[0].clipId) s.clipId = results[0].clipId;
// results[0] 可能是占位，clipId 为 null
const okResults = results.filter(p => p.clipId && p.status !== 'split');
if (!s.clipId && okResults.length) s.clipId = okResults[0].clipId;
```

### ③ 二分树日志

```js
const stats = { done: 0, split: 0, byDepth: {} };
pieces.forEach(p => {
  const st = p.status || (p.clipId ? 'done' : 'split');
  stats[st] = (stats[st] || 0) + 1;
  const d = p.depth || 0;
  stats.byDepth[d] = (stats.byDepth[d] || 0) + 1;
});
log('切片统计：共 ' + pieces.length + ' 片，成功 ' + (stats.done || 0) +
    '，失败占位 ' + (stats.split || 0) + '（' + depthStr + '）');
```

输出示例：`切片统计：共 8 片，成功 8，失败占位 0（d0=2 d1=6）`

## 七、这次改造的价值

**修复的死代码 bug 比占位机制更值钱。**

二分从未生效意味着：
- 被拒的段直接丢弃
- 用户看到的成品有内容缺失
- 而且日志说「完整性校验通过」，**误导用户以为是完整的**

修复后：
- 被拒的段自动拆成两半重试
- 30 秒素材从「2/5 成功」变成「8/8 全成功」
- 日志如实报告成功/失败数量

**这个 bug 从 v38 就存在，一直没人发现，因为没人核对过「切 0 层」的含义。**
