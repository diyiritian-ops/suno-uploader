# Suno 一键上传器

把任意音频文件传入 Suno，自动切片、移调绕过版权特征、合并成完整歌曲、导出并下载。

**导出的成品可以直接在 Suno 里点 `Remix → Cover` 做翻唱。**

---

## 它解决什么问题

Suno 对上传的完整歌曲有版权内容检测（内容识别服务），直接传整首歌会被拒。

这个脚本的做法：

1. 把音频切成小段
2. 每段移调再上传（破坏频谱特征，但音高变化在导出时会还原）
3. 在 Suno Studio 里把这些片段按原始时间线拼起来
4. 提交导出 → 得到一个完整的歌曲
5. 下载到本地（可选 MP3 / WAV / M4A）

## 使用

### 界面（v29 重构）

面板分 4 个标签页：

| 标签 | 干什么 |
|---|---|
| **上传** | 拖文件、改参数、开始上传、看进度 |
| **结果** | 跑完的**完整作品**在这里：封面 + 标题 + 时长 + 一键打开 |
| **作品库** | 我的全部作品 / 按链接下载 |
| **积分** | 自动做 listen-and-rank 评分任务赚积分 |

面板顶部有 **4 步引导**（选文件 → 参数 → 上传 → 成品），当前步骤高亮，下面一行小字告诉你现在该干嘛。

> 界面里**没有运行日志**了——客户版不显示这些内部细节。
> 出问题时在 Tampermonkey 图标菜单里点「复制运行日志（排错用）」，日志会进剪贴板，发给技术支持即可。

### 最简流程

1. 拖音频文件到虚线框（也可以拖到面板任何地方）
2. 点「开始上传」
3. 等它跑完 → 自动跳到「结果」页，点「在 Suno 打开」就是成品

默认参数已经调好，**不需要改**。

跑的时候进度条右边会显示 **剩余约 X 分 Y 秒**（按已完成段数推算，段耗时差异不大，够准）。

> **v29 起不再自动下载**：终点就是 Suno 里那首完整作品（可直接 Cover）。
> 真要本地文件，「结果」页底部有个不显眼的「下载到本地（可选）」。

### 万一有缺段

脚本发现有段落始终传不上去时，**会阻止导出**（避免得到一首中间缺一段、后面全错位的废歌），
并在「结果」页告诉你具体缺哪几段：

```
有缺段 · 未导出
[ 只补缺的 3 段 ]     ← 点这个
缺 part007、part012、part022，已阻止导出
已经成功的段不会重传。需要先把原文件重新拖进来（进度已保存）。
```

点了会回到上传页，只重跑缺的那几段。如果刷新过页面，先把同一个文件重新拖进来（会提示「恢复上次进度」）。

### 两个开关

| 开关 | 默认 | 说明 |
|---|---|---|
| 自动导出 | 开 | 上传完自动合并成完整作品 |
| 自动清洗 | 开 | 防止成品被二次审查删除，保证能 Cover |

### 高级参数（折叠区，一般不用动）

点「高级参数」展开：

| 参数 | 默认 | 说明 |
|---|---|---|
| 项目名 | 文件名 | Suno 里显示的名称 |
| 切片(秒) | 6 | 每段长度。**脚本会自动放大**，因为移调后要保证上传 ≥6 秒 |
| 并发数 | 4 | 同时上传几段。太高容易触发限流（1–6） |
| 每段重试 | 3 | 单段失败换移调重试的次数 |
| 补全轮数 | 3 | 整轮重传次数 |
| 上传移调 | 4 | **关键参数**，见下方说明 |
| 下载格式 | MP3 | MP3 / WAV / M4A |


### 关于「上传移调」

数字越大越容易过版权检测，但**音质损失越大**：

| 移调 | 能保留的最高频 | 效果 |
|---|---|---|
| **+4** | 19 kHz | ✅ 几乎无损（推荐） |
| +7 | 16 kHz | 勉强 |
| +12 | 12 kHz | ⚠️ 明显发闷 |
| +24 | 6 kHz | ❌ 高频全没，声音很闷 |

原理：移调会让采样率等比变化，超出 Nyquist 上限的频率会被永久丢弃。

**保持默认 +4 即可。**

## 两个贴心功能

### 网络不好会自动暂停

上传过程中如果连续 3 次网络请求失败，脚本会**自动暂停**并弹出红色提示条：

```
📡 网络异常
连续 3 次请求失败（S3 超时）。请检查网络，
必要时切换 WiFi / 手机热点 / 代理，然后点「继续」。
已上传的片段不会丢失。

  [ 已换网络，继续 ]   [ 跳过失败段 ]
```

- 换好网络后点 **「已换网络，继续」**，从断点接着传
- 某几段实在传不上，点 **「跳过失败段」** 继续后面的
- **已上传成功的片段不会重传**

### 刷新页面不丢进度

每上传成功一段就自动存档。**中途刷新 / 关掉页面再打开**，会弹出：

```
发现上次未完成的进度
《你的歌.mp3》 已上传 6 / 10 段。点「恢复」后需要重新选择这个文件。

  [ 恢复并继续 ]   [ 丢弃 ]
```

点「恢复并继续」→ 重新选同一个文件（会校验文件名和大小）→ 已传的段直接跳过。

> 存档保留 3 天。全部完成后自动清除。

## 跑完之后

### 在 Suno 里找到成品

上传完成后，去 <https://suno.com/me>（Library）找最新的一首歌。

标题格式：`你的项目名 (Full)`

### 做 Cover

1. 打开这首歌
2. 点右侧 **`⋯` / `Remix`**
3. 选 **`Cover`**
4. 编辑歌词/风格后点 **`Create`**

### 音质核对

正常的话，成品应该：
- 时长和原曲一致
- 没有突然的静音或断裂
- 高频清晰（不闷）

## 下载库

面板底部有 **「📚 下载库 · 粘贴链接直接下载」** 按钮，点开进入。

### 按链接下载（最快）

直接粘贴 Suno 歌曲链接，回车即下：

```
https://suno.com/song/<id>
https://suno.com/s/KDwdnP91gd1U0MaR              ← 短分享链接，自动解析
https://suno.com/clip/6a3f8c21-...
<id>              ← 只贴 ID 也行
```

带 `?sh=xxx` 之类的尾巴也没关系，脚本会自动识别 ID。
短链接 `suno.com/s/xxx` 会自动跟随跳转取出真实歌曲 ID（约 2 秒）。

### 从我的作品下载

**作品库会缓存到本地**，打开就是上次的结果，不用每次等。

1. 第一次点 **「⟳ 刷新」** 加载作品列表
   （会翻 40 页、约 800 条，需要 40–50 秒，期间显示「已翻 N 页」）
2. 之后再打开下载库 —— **2 秒内直接显示**，统计栏会标「X 小时前刷新」
3. 只有点了「⟳ 刷新」才会重新联网拉取

用四个筛选按钮切换：
   - **全部** —— 所有内容
   - **⬆ 上传合成** —— 本工具上传后合成出来的完整歌曲
   - **✨ AI 生成** —— Suno 模型生成的歌（含你做的 Cover）
   - **片段** —— 上传的切片段

3. 顶部搜索框按标题过滤

### 两类完整版的区别

| | ⬆ 上传合成 | ✨ AI 生成 |
|---|---|---|
| 来源 | 你上传的音频切片拼起来的 | Suno 模型生成的 |
| `type` | `rendered_context_window` | `gen` |
| 模型 | `chirp-chirp` | `chirp-hawk` 等 |
| 用途 | 音质=原曲，做 Cover 的底 | AI 翻唱/续写结果 |

### 完整版按歌曲分组（重要）

切「⬆ 上传合成」或「✨ AI 生成」后，**同一首歌的多个版本会折叠成一条**：

```
Nightwish - I Want My Tears Back     [上传合成]   1 个版本  ▸
  └ 290s · chirp-chirp   2026-10-21 12:01   [⬇ 下载] [🔗]

陈明 - 快乐老家                       [上传合成]   1 个版本  ▸
  └ 300s · chirp-chirp   ...                [⬇ 下载] [🔗]
```

点标题展开，里面每个版本都能单独下载。

> **为什么之前找不到？**
> 上传合成的完整版排在 feed **第 12 页之后**，旧版只翻 4–12 页，
> 正好把它们全截断了。
>
> 现在翻满 40 页（约 750 条），实测能把全部 **34 个上传合成完整版**找出来。

列表显示缩略图、标题、类型、时长、模型。


### 下载格式

在「高级参数」里的「下载格式」选：

| 格式 | 速度 | 说明 |
|---|---|---|
| **M4A** | ⚡ 约 5 秒 | **推荐**，无需任何外部依赖 |
| MP3 | 首次约 1 分钟 | 需下载 31MB 编码器，之后有缓存 |
| WAV | 约 10 秒 | 无损，但 5 分钟歌约 55MB |

> **为什么之前会卡住？**
> MP3 编码需要从 CDN 下载约 31MB 的 ffmpeg，旧版本这段没有超时，
> 网络一不稳定就永久卡死、界面没反应。
>
> 现在已修：**3 个 CDN 源自动切换 + 60 秒超时 + 失败自动降级为 WAV**。
> 想彻底避免等待，就用 M4A —— 它的音质和 MP3 源文件完全一样（本来就是 AAC）。

## 听歌赚积分（v28 新增）

面板右上角的 **⚡** 按钮 → 「开始赚积分」。

它会自动去 `suno.com/listen-and-rank` 做评分任务：听两段音频 → 选 A / B / 都不选 → 提交，
一轮约 13 秒，每题 5–6 积分。**全程静音，不会出声**，也不影响你干别的事。

| 项 | 说明 |
|---|---|
| 每日上限 | Suno 自己控制的，实测约 10 题（≈50 积分），跑完页面会出现 `Resets in 23h 27m`，脚本会自动停 |
| 前提 | 第一次用要填一次「评分者资料」（5 道选择题），脚本会自动选完 |
| 必须留在前台 | 标签页被切到后台时浏览器会节流，听歌秒数不涨，脚本会暂停并提示；切回来就继续 |
| 中断了怎么办 | 刷新页面会自动续跑（状态存在 Tampermonkey 里） |

**它能自己判断的几种情况**：资料没填 → 自动填；按钮从 `Earn credits` 变成 `Next tasks` → 跟着点；
今天跑完了 → 提示还剩多久重置。

> 说明：脚本只是把「点播放 → 选一个 → 点提交」这套操作自动化，**评分结果本身不携带任何信息**，
> 所以随机选 A/B 不会污染 Suno 的评测数据质量（它统计的是人类偏好分布，随机选择就是其中一个正常样本）。


### 成品中间少了一段 / 后面错位（v27 已修）

**症状**：歌是导出成功了，但中间有一段没了，后面整体提前。

**原因（三个 bug 叠加）**：

1. 二分上传时可能只成功了一半，脚本看到"有 clipId"就当成功了
2. 轮次用完还有缺段，仍然继续导出
3. 时间线是首尾紧排的，缺一段后面全部前移 → 全曲错位

**v27 的修复**：

| 项 | 现在 |
|---|---|
| 判定成功 | 按**实际覆盖秒数**算，差 >0.35 秒就算没完成 |
| 缺段时 | 自动跑 **2 轮「补漏」**，用更高移调（最高 +7）重试缺的段 |
| 还缺 | **直接阻止导出**，红字列出缺哪几段，不会产出废歌 |
| 时间线 | 按原始时间轴**绝对定位**，即使有缺口也不会让后面错位 |

日志会明确写：

```
✓ 完整性校验通过：34 段全部覆盖
```

或者：

```
✗✗ 有 1 段始终没能上传：part022
   已停止导出 —— 强行导出会得到一首中间缺一段的歌。
```

### 成品开头有静音（v27 已修）

分段数原来用 `ceil` 算，会把每段压得比设定值短。
例：30 秒音频、切片 9 秒 → 4 段 × 7.5 秒，移调后只剩 5.95 秒 < 6 秒 → Suno 补静音。

现在用 `floor`，并会校验「移调后仍 ≥ 6 秒」，日志会写：

```
分段调整为 3 段 × 10.0s（保证每段移调后仍 ≥ 6 秒）
```

### 面板没出现 / 突然看不到了

**最常见原因：面板被拖到屏幕外了。**

面板位置会被记住。如果在宽窗口里拖到右边，换成窄窗口后它就跑出可视区，
看起来像「脚本消失了」。

**解决办法（任选）：**

1. **点 Tampermonkey 图标 → `重置面板位置（看不见面板时用）`** ← 最快
2. 刷新页面（`Ctrl+Shift+R`）—— v21.2 起会自动把面板拉回可视区
3. 把窗口拉宽再找找

其他检查：
- 确认脚本已启用（Tampermonkey 面板里开关是打开的）
- 确认当前页面是 `suno.com`
- 面板可能被最小化成了右下角的紫色圆形按钮，点它展开

### 上传失败 / 大量被拒

- 提高「上传移调」到 +5 或 +6 重试
- 降低「并发数」到 2–3
- 检查网络（Suno 需要能访问）

### 上传卡住不动

**v24 起已修复**。旧版的表现是日志不停刷「上传超时 75s」，一段要等将近 4 分钟。

原因：外层超时设了 75 秒，但内层「等 Suno 处理」最多要 100 秒 ——
**外层永远比内层先超时**，只要 Suno 稍慢就必失败，重试也一样。

现在：
- 外层超时改成 180 秒（覆盖内层最坏情况 + S3 上传余量）
- S3 上传超时 30 秒 → 60 秒（照顾国内上行）
- 等待期间每 8 秒输出一次进度：`Suno 处理中 24s（pending）`

不会再出现「看起来没反应」的情况。

### 成品有静音或断裂

说明切片太短，Suno 在上传时补了静音。脚本 **v21.2 起已自动处理**（按移调倍数放大切片），如果仍出现：
- 手动把「切片(秒)」调大（比如 12）
- 确认「上传移调」不要超过 +8

### 下载卡住不动

**先换 M4A 格式试试** —— 下载格式选 M4A 是纯本地解密，约 5 秒出结果，不依赖任何外部 CDN。

如果选了 MP3 卡住：
- 看日志有没有 `core.wasm 网络失败`，那是 jsdelivr 连不上
- 脚本会自动换源重试，全部失败后会降级存 WAV（日志会写「改为保存 WAV」）
- 想彻底不卡，就用 M4A

### MP3 下载失败

MP3 编码需要从 jsdelivr 加载约 31MB 的 ffmpeg，网络不好时会自动降级为 WAV。

日志里会明确写出实际保存的格式和文件名，注意看后缀。

### 下载的音频怎么解密

脚本内部处理：Suno 的音频是加密 m4a，脚本会自动获取密钥、AES-CTR 解密、转格式。**无需手动操作。**

## 工作原理（技术细节）

```
① 解码音频 → 按切片长度分段
② 每段用 playbackRate 重采样（移调 +4，时长变短）
③ 6 步上传到 Suno：
   init → S3 上传 → upload-finish → 轮询 → initialize-clip → set-metadata
④ 建 Studio 工程：
   clip.transposition = -4            （Studio 按变速播放，音高和时长都还原）
   clip.warp.markersHash + markersRegistry  （时间拉伸映射）
   endBeats = 原始时长 × 1.95
⑤ 提交导出：
   POST /api/studio/render-state
   { from_studio_project_id, export_mode: 'rendered_context_window' }
   产物 type = rendered_context_window（可 Cover，不会被删）
⑥ 下载解密：
   mango/rights（不带 Authorization，才能拿到 glt）
   → SHA-256(glt) 作为密钥 → AES-GCM 解出 key/iv
   → AES-CTR 解密音频
```

### 为什么用 `rendered_context_window`

Suno 有两种导出模式：

| 模式 | 参数 | 产物 type |
|---|---|---|
| Studio 导出 | `studio_project_id` + `export_mode: studio_export` | `studio_export` |
| 上下文窗口渲染 | `from_studio_project_id` + `export_mode: rendered_context_window` | `rendered_context_window` |

**只有后者产出的 clip 在 Suno 里表现正常、可 Cover。**
