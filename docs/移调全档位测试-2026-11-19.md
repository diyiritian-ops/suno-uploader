## 二、站点 0 移调的关键发现

### 发现 1：0 移调时文件名没有 `_processed_pitch` 后缀

```
0 移调：  【4K30FPS】...(Av763790973,P1)_YC-SUNO-UPLOADER_part001.wav
+23 移调：senorita_processed_pitch+23_YC-SUNO-UPLOADER_part001.wav
```

**说明**：0 移调时它**完全跳过音频预处理**，直接按原速切片上传。
非 0 时才做 `processed_pitch+N` 的整首移调。

### 发现 2：0 移调让切片数从 35 暴涨到 115

```
初始（预处理后）：35 段
运行 20 分钟后：115 段（50 → 115 持续增长）
```

**原因**：`失败片段自动二分`在起作用。

0 移调时音频**完全没变**，指纹必然命中。
被拒绝的段自动原位拆成两半重试，最多拆 4 层：

```
原始段 6 秒
  └ 第 1 层：3 + 3 秒
      └ 第 2 层：1.5 + 1.5 秒
          └ 第 3 层：0.75 + 0.75 秒
              └ 第 4 层：0.375 + 0.375 秒
```

35 段全部被拒 → 二分 → 最多产生 35 × 2^4 = 560 个子段。
实际最终 115 段，说明大部分在 1-2 层就过了。

**经验**：**0 移调不是"不做处理"，是靠"拆得更碎"来绕过指纹。**

### 发现 3：429 风控

```
429 风控第 1 次 · 已完成 2/35 · 当前 part013
阶段 complete · 接口 status · 距上次成功 0.4 秒
本次冷却 180 秒 · 累计冷却 180 秒
```

**触发条件**：连续上传太快（距上次成功仅 0.4 秒）。
**它的处理**：自动冷却 180 秒后继续，不报错。

**经验**：并发 6 + 上传间隔 2 秒太激进，会触发风控。
它自己会用 180 秒冷却兜底，但整体速度被拖慢。

### 发现 4：成品类型是 `edit_crop`

对比之前 +23 的成品是 `rendered_context_window`：

| 移调 | 成品类型 |
|---|---|
| +23 | `rendered_context_window` |
| **0** | **`edit_crop`** |

**推测**：0 移调时它走了"全部子段拼装 + 清洗"的路径，
最终产物被 Suno 标记为 `edit_crop`（编辑裁切型）。

## 六、给脚本的启示

从站点学到的三点，脚本可以借鉴：

### 1. 0 移调时的策略

站点在 0 移调时**不放弃预处理**，而是靠二分硬刚。
脚本当前 0 移调时是原速切片，也没问题，但可以考虑：
- 0 移调时自动提示"段数会很多，建议至少 +5"

### 2. 二分层级控制

站点最多 4 层（6 → 3 → 1.5 → 0.75 → 0.375 秒）。
脚本的 `uploadWithBisect` 也有二分，但需要确认层数限制。

### 3. 风控退避

站点的 180 秒冷却机制值得借鉴。
脚本当前是 3 秒重试，太激进。
